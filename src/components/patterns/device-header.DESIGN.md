# Device header

DeviceHeader owns the dark rounded header, shared Plus Jakarta Sans SepCare wordmark at its 21px large size, content-sized square device tile, connection label and battery percentage, and two shared Button actions. Device name and action handlers are supplied by consumers. `connected` defaults to true; false changes the label and makes the last-known percentage neutral. Baby health never changes the connection state.

Header surface and action colors use `--color-device-header-*`. DeviceTileRow shares the `--color-device-{state}-{surface|icon}` roles with DeviceCard. Optional `battery` uses the provisional >50 / 21–50 / 0–20 thresholds; disconnected always overrides the battery state. The healthy tile is green-100 with a darker green glyph; Button uses its supported colors API. The web header starts with the wordmark and actions; device time, cellular signal, and system battery belong to the operating system and are not simulated. The shared composition is demonstrated in motion docs and consumed by the clinical dashboard. The header stays above the scrolling clinical content and caps its inner content width on wider viewports.

The header displays the optional battery percentage followed by a thin decorative divider and a small non-emoji PulseWave beside the connection label. The pulse shares device tone and is static when disconnected or reduced motion is enabled. Missing or nonfinite battery and its divider are omitted. Header battery text uses --color-device-header-battery-{healthy|medium|low|disconnected}, lighter palette shades for the dark surface, with the same green/yellow/red/neutral states and thresholds as Settings. The clinical example supplies the same 90% to the header and Settings.

## Consistent example scenarios

The Safe / Caution / Critical preview control applies across Home, Vitals, Stats, and Settings without resetting navigation. Fixtures in src/lib/examples/clinical-scenarios.ts supply per-vital states: safe detail rows and Stats graphs are all green, while Home VitalCards retain their three distinct metric gradients; caution uses yellow thermoregulation and cardiac autonomic, red activity, and three green vitals; critical is all red. Stats graphs, icons, and values use the same per-vital states as Vitals. Infant headings and descriptions follow the overall scenario. These are illustrative combinations, not rules for computing infant risk.

Device fixtures use 90%, 40%, and 15% respectively; caution displays Slow internet. DeviceHeader.slowInternet is an independent boolean, defaults false, and disconnected takes precedence. Device battery stays consistent across header and device cards. Clinical state never computes battery or connectivity in shared components.

VitalDetailCard accepts optional status (safe/caution/critical), which controls the icon, value, and graph lines together. Explicit status overrides legacy critical. If neither is supplied, the header defaults green and series retain supplied colors. VitalCard retains each metric gradient for safe or omitted status. Caution uses yellow and critical uses red. Filled VitalCards always use white labels, icons, sparklines, and values. Activity text uses the same font-heading text-2xl font-bold as numeric readings.
