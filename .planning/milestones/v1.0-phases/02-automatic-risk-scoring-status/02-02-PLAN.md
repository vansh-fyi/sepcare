    In `src/lib/risk/thresholds.ts`, export named constants with D-reference JSDoc comments:
    `TEMP_FEVER_C = 38.0`, `TEMP_HYPOTHERMIA_C = 35.5` (D-13's asymmetric >=/< boundary),
    `HR_TEMP_RATIO_MIN = 6`, `HR_TEMP_RATIO_MAX = 14` (Liebermeister band, inclusive-normal),
    `MIN_DELTA_TEMP_C = 0.1` (below this the HR/temp ratio is not computable — avoids a
    near-zero-denominator blowup), `ACTIVITY_DECLINE_RATIO = 0.7` (current activityScore at or
    below 70% of the personal baseline counts as declining — D-14's trend, expressed as a ratio
    rather than an absolute unit since activityScore has no documented fixed range),
    `TREND_WINDOW_MS = 12 * 60 * 60 * 1000` (D-15), `BASELINE_MIN_MS = 60 * 60 * 1000` (D-18).

    In `src/lib/risk/compute.ts`, export a `TargetReading` interface (`id: number, deviceId:
    string, timestamp: number, heartRate: number, temperature: number, activityScore: number`)
    and a `RiskBreakdown` interface matching RESEARCH.md's Code Examples shape exactly
    (`temperature: {abnormal: boolean, value: number}`, `hrTempProportionality: {abnormal:
    boolean, ratio: number | null}`, `activityTrend: {trending: boolean, delta: number |
    null}`). Export `async function computeAndPersistRiskScore(target: TargetReading):
    Promise<{status: "green" | "amber" | "red"; breakdown: RiskBreakdown}>` that: (1) queries
    `supabaseAdmin.from("readings").select("id, timestamp, heartRate, temperature,
    activityScore").eq("deviceId", target.deviceId).lte("timestamp",
    target.timestamp).gte("timestamp", target.timestamp - TREND_WINDOW_MS).order("timestamp",
    {ascending: true}).order("id", {ascending: true})`, throwing on `error` (D-26's causal
    window — never reads a row with `timestamp` after `target.timestamp`); (2) derives
    `baselineEstablished` from `target.timestamp - (window[0]?.timestamp ?? target.timestamp) >=
    BASELINE_MIN_MS` (D-18); (3) builds `prior` as every window row with `timestamp` strictly
    before `target.timestamp`, OR equal `timestamp` with a strictly smaller `id` (excludes the
    target reading itself even under duplicate-timestamp ties); (4) evaluates the temperature
    feature unconditionally as `target.temperature >= TEMP_FEVER_C || target.temperature <
    TEMP_HYPOTHERMIA_C` (D-13, no baseline required); (5) when `baselineEstablished &&
    prior.length > 0`, computes `baselineHR`/`baselineTemp` as the arithmetic mean of `prior`'s
    `heartRate`/`temperature`, `deltaTemp = target.temperature - baselineTemp`, `deltaHR =
    target.heartRate - baselineHR`; if `Math.abs(deltaTemp) < MIN_DELTA_TEMP_C` the ratio is not
    computable (`ratio: null, abnormal: false`), else `ratio = deltaHR / deltaTemp` and
    `abnormal = ratio < HR_TEMP_RATIO_MIN || ratio > HR_TEMP_RATIO_MAX`; when baseline is not
    established, `ratio: null, abnormal: false`; (6) when `baselineEstablished && prior.length >
    0`, computes `baselineActivity` as the mean of `prior`'s `activityScore`; if
    `baselineActivity > 0`, `delta = target.activityScore - baselineActivity` and `trending =
    target.activityScore <= baselineActivity * ACTIVITY_DECLINE_RATIO`; if `baselineActivity` is
    `0` or baseline is not established, `delta: null, trending: false`; (7) counts how many of
    the 3 booleans (`temperature.abnormal`, `hrTempProportionality.abnormal`,
    `activityTrend.trending`) are `true` and maps `count >= 3 -> "red"`, `count === 2 ->
    "amber"`, else `"green"` (D-12 — count is a plain integer sum, comparisons are exact); (8)
    upserts `{ reading_id: target.id, deviceId: target.deviceId, status, breakdown }` into
    `supabaseAdmin.from("risk_scores")`, throwing on `error`; (9) returns `{ status, breakdown
    }`.
