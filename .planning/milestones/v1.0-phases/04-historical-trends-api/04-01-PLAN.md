<flagged_assumptions>
## Spec-less probe disposition

- **Adjacency — explicit residual assumption:** the storage query uses inclusive `gte(from)` and `lte(to)` bounds, matching the established risk-window pattern. A single response cannot duplicate a timestamp because Phase 3 made same-device timestamps unique. Two independently requested adjacent inclusive ranges can each contain their shared boundary record; no half-open interval convention, cursor, or deduplication state was decided, so do not invent one.
- **Empty — resolved:** D-42 requires a valid range with no records to return `200` and an empty `entries` array.
- **Ordering — resolved:** D-46 requires original `timestamp` ascending. The same-device uniqueness constraint makes a secondary tie-break unnecessary for this endpoint.
- **Concurrency — explicit residual assumption:** pages are independent latest-state queries. A concurrent ingest/backfill can change what later pages see, so the route does not promise a transactional snapshot. `Cache-Control: no-store` and the existing Realtime-triggered refetch model prioritize subsequent freshness; locks, snapshot export, and a cursor protocol are outside the locked v1 scope.
</flagged_assumptions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public dashboard -> GET route | Untrusted device/range query parameters enter an intentionally public route. |
| GET route -> supabaseAdmin | The service-role client bypasses RLS and therefore requires a route-level allow-list before querying. |
| Supabase result/error -> HTTP response | Persisted data is transformed into a public DTO; database failures must remain server-only. |
| database/Reatime backfill -> browser cache | Offline batch backfills and rescoring need a fresh response rather than a stale browser/proxy object. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information disclosure | `GET /api/readings` -> `supabaseAdmin` | high | mitigate | Validate exact `deviceId === "nb-001"` before any query; missing ID is 400 and every other present ID receives D-39's fixed 404. |
| T-04-02 | Denial of service | range parser/page loop | medium | mitigate | Require strict safe-integer epoch-ms values, `from < to`, a 15-day maximum, and fixed 1,000-row pages. |
| T-04-03 | Information disclosure | route failure response | medium | mitigate | Log caught Supabase errors with server-only `console.error`; return only D-49's fixed 500 body. |
| T-04-04 | Tampering | stale trend representation | medium | mitigate | Apply `Cache-Control: no-store` to every success/error response so Realtime-triggered refetches retrieve current storage state. |
| T-04-05 | Repudiation | malformed public requests | low | mitigate | In non-production, `console.warn` a stable field/reason diagnostic without credentials or user data; tests prove this path. |
| T-04-06 | Tampering / race | paginated history under concurrent ingest | low | accept | v1 has no snapshot/cursor contract; retain explicit residual assumption and no-store/refetch freshness rather than adding locks outside scope. |
| T-04-SC | Tampering | package installs | high | mitigate | No package install is planned; Package Legitimacy Audit is not applicable. |
</threat_model>
