# Phase 7 data-contract diff

This is Phase 8's primary planning input (D-09): the field and endpoint gaps surfaced by the caregiver and parent prototype. **All Phase 7 fixture data is synthetic, not validated against real device telemetry.** Matching the current response shape and scoring formulas does not validate sensor accuracy or clinical performance. Evidence below is from the checked-in implementation on 2026-10-01; no live schema introspection or firmware measurement was performed.

## Existing contract to preserve

- `src/lib/fixtures/readings.ts` mirrors `{ deviceId, from, to, entries: [{ timestamp, vitals, risk }] }`. Risk can be `null`; ratio and activity delta can be `null` during baseline establishment. Absence is not a healthy classification.
- Supported summaries use temperature, computed `ΔHR/ΔTemp`, and activity score/trend. `src/lib/fixtures/vital-metrics.ts` maps these explicitly; do not substitute SpO2 for perfusion, raw heart rate for HRV, or fabricated respiratory values.
- Current risk is the existing three-feature rule, not a completed six-feature model. Backend `green/amber/red` maps to UI `safe/caution/critical`; individual feature flags are separate from composite risk.
- Keep every original reading and its epoch-millisecond timestamp. Chart tick cadence does not change acquisition cadence. Synthetic 1–3-minute spacing is illustrative, not a confirmed firmware interval.
- Device selection is one `nb-001` entry. Multi-device ownership/auth remains the separately recorded `ACC-V2-01` scope decision; the registry secret must remain server-side regardless. No new auth or device service is implemented by this document.
- Phase 10 means replacing fixtures with live data in existing Next.js routes, per D-01/D-02, rather than porting a detached HTML app.
