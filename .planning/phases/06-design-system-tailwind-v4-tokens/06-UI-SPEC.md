## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge inner padding |
| sm | 8px | Compact element spacing, list row spacing |
| — | 12px | **Exception** — input vertical padding, compact card separation (see below) |
| md | 16px | Default element spacing, button padding, card element gap |
| lg | 24px | Default Card internal padding, section margin |
| xl | 32px | Section-to-section spacing |
| 2xl | 48px | Major viewport section divisions |
| 3xl | 64px | Page-level top/bottom padding |

Exceptions:
- **12px** — used specifically for `Input` vertical padding and compact card-row separation (carried forward from the salvaged `tokens.css`/`DESIGN-SYSTEM.md` §5). It is off the strict 8-point ladder but already Tailwind-native (`p-3` = 0.75rem = 12px), so no custom token is needed.
- **44×44px minimum touch target** — icon-only `Button` (icon variant) and any toggle control. Maps directly to Tailwind's `size-11` (`w-11 h-11`).

**Tailwind v4 implementation note:** do **not** redeclare a custom `--spacing-*` scale in `@theme`. Tailwind v4's stock `--spacing: 0.25rem` primitive already generates every value above via standard utilities (`p-1`→4px, `p-2`→8px, `p-3`→12px, `p-4`→16px, `p-6`→24px, `p-8`→32px, `p-12`→48px, `p-16`→64px, `size-11`→44px). Only add a custom spacing token if a step outside this set is ever required.

## Typography

Phase 6 typography contract covers **only** what the 4 atomic components need. `display`,
`heading-page`, `vital-metric`, and other large/bold roles from the salvaged type scale are
real and will return, but are out of scope until the composite/full-screen phase (Phase 7)
that actually renders them — declaring them here would blow the 3–4 size / 2 weight budget for
no reason this phase can exercise.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Heading (Card title) | 18px | 600 (semibold) | 1.3 |
| Body (default text, Input value) | 16px | 400 (regular) | 1.5 |
| Label (Badge/StatusPill label, Input label) | 13px | 600 (semibold) | 1.4 |
| Caption (helper text, error text, unit text) | 12px | 400 (regular) | 1.4 |

Exactly 2 weights total: **400 regular**, **600 semibold**. `Button` label text reuses the
already-declared **Body size (16px)** at the already-declared **Label weight (600)** — this is a
recombination of the two values above, not a new (size, weight) pair.

Font: **Inter** (`--font-sans` in `@theme`), fallback stack `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` (from the salvaged `tokens.css`).

Tailwind v4 note: declare via the `--text-*` namespace with the paired line-height suffix, e.g.:
```css
--text-heading: 1.125rem;         /* 18px */
--text-heading--line-height: 1.3;
--text-body: 1rem;                /* 16px */
--text-body--line-height: 1.5;
--text-label: 0.8125rem;          /* 13px */
--text-label--line-height: 1.4;
--text-caption: 0.75rem;          /* 12px */
--text-caption--line-height: 1.4;
```

## Color

The project's own canonical reference (`DESIGN-SYSTEM.md` §3.1) documents a **70% neutral /
20% soft-pastel / 10% interaction+status** balance, not a generic 60/30/10 split — that ratio is
intentional and carries forward unchanged; only the pink hue's *role* changes (D-04).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (~70%) | `#F7F9FC` (bg) / `#FFFFFF` (card surface) | Page canvas + card/surface backgrounds. Text on these: `#182235` primary |
| Secondary (~20%) | `#EEF5FC` soft-blue, `#F3F0FA` soft-lavender, `#FBF1F2` soft-blush, `#FCF4EA` soft-peach | Atmospheric card tints, sidebar panels, insight callouts — contextual, not brand |
| Accent (~10%) | `#6F9FD5` brand blue | Reserved for: interactive elements only — links, focus rings, selected/active states, default icon tint. **Never** used to denote infant health status |
| Destructive/Critical | `#BF4884` (`critical-fill`, accessible on-fill shade — see below) | Reserved for the `Button` `critical` variant (urgent clinical action, e.g. "Call Clinician") and the Critical status state. No delete/remove-type destructive action exists in Phase 6's atomic component set |

Accent (`#6F9FD5`) reserved for: `Button` `primary`/`tertiary` text-on-transparent or link color,
`Input` focus ring/border, any future selected/active nav state. Not for status, not for
secondary/critical buttons.

### Tri-state health-status system (unchanged structure, pink hue swapped in for Critical only — D-04)

| Status | Primary (icon/dot, non-text UI) | On-fill (Button/high-contrast text use) | Soft (badge/alert bg) | Dark (badge/alert text) |
|--------|-------|-------|------|------|
| Safe | `#4FAF78` | — (no filled-button use this phase) | `#EAF6EF` | `#27734B` |
| Caution | `#D9A52E` | — (no filled-button use this phase) | `#FFF6DF` | `#89691A` |
| Critical | `#CF5792` | `#BF4884` | `#FAECF2` | `#8F3763` |

**Why two critical shades, not one:** the salvaged critical red (`#D95757`) only produced
white-on-fill contrast of 3.87:1 — a pre-existing gap. Re-deriving in OKLCH per the project's
color rules (hold hue + chroma, move lightness only) fixed it: `critical` (`oklch(0.626 0.164
352)` ≈ `#CF5792`) is for icons/dots/non-text UI (3:1 floor, met); `critical-fill`
(`oklch(0.58 0.164 352)` ≈ `#BF4884`) is a darker step of the *same* hue reserved for
white-text-on-fill contexts (`Button` `critical`), giving 4.69:1 (AA). `critical-soft`/`critical-dark`
already had 6.34:1+ and are untouched. Hue **352°** was chosen because it reads as a true clinical
rose-pink — distinct from both the old red (hue 23°) and Tailwind's stock "rose" (hue ~18°,
effectively the same hue as the color being replaced) — and distinct from a pastel "baby pink"
(which sits at much higher lightness / lower chroma than this).

Same pattern applies to `brand`: `#6F9FD5` (`oklch(0.69 0.095 252)`) stays as the light accent for
non-fill uses; a new `brand-fill` step `#4977AB` (`oklch(0.56 0.095 252)`) is added specifically
for `Button` `primary` background (white label text, 4.66:1 vs. the salvaged blue's 2.76:1). This
is a genuine accessibility fix uncovered while re-deriving the palette, not a stylistic departure
— same hue, same "loved" blue, just a second on-fill step next to the existing light one.

## Surface Tokens (Radius, Shadow, Motion)

Not a template-mandated section, but core Phase 6 deliverable content the planner/executor need
— carried forward unchanged from the salvaged `tokens.css` (D-04 only touches status *color*,
not geometry), re-expressed for Tailwind v4's `--radius-*` / `--shadow-*` namespaces.

**Radius** (`--radius-*`, generates `rounded-{name}` utilities):

| Token | Value | Usage |
|-------|-------|-------|
| `--radius-input` | 12px | `Input` |
| `--radius-btn` | 14px | `Button` |
| `--radius-card-sm` | 16px | Compact/secondary cards |
| `--radius-card` | 20px | Standard `Card` |
| `--radius-hero` | 24px | Status hero card, alert banners (future phase) |
| `--radius-modal` | 28px | Modals/sheets (future phase) |
| `--radius-full` | 9999px | `Badge`/StatusPill pill shape |

**Shadow** (`--shadow-*`):

| Token | Value | Usage |
|-------|-------|-------|
| `--shadow-card` | `0 4px 20px rgba(24, 34, 53, 0.05)` | `Card` default elevation |
| `--shadow-floating` | `0 8px 30px rgba(24, 34, 53, 0.08)` | Dropdowns, popovers (future phase) |
| `--shadow-critical` | `0 10px 32px rgba(207, 87, 146, 0.12)` | **Updated** — rgb of new pink `critical` (`#CF5792`), was `rgba(217, 87, 87, 0.12)` on the old red |
| `--shadow-focus` | `0 0 0 3px rgba(111, 159, 213, 0.25)` | Focus-visible ring on interactive elements (unchanged, uses light `brand`) |

**Motion** (durations only this phase — full easing/spring guidance deferred to when actual
transitions are implemented):

| Token | Value | Usage |
|-------|-------|-------|
| `--duration-fast` | 150ms | Hover/press micro-feedback |
| `--duration-normal` | 250ms | Default transitions (focus ring, color change) |
| `--duration-slow` | 350ms | Loading skeleton pulse, larger state changes |

Easing: `cubic-bezier(0.4, 0, 0.2, 1)` for all three (unchanged). Respect
`prefers-reduced-motion` on any skeleton pulse / spinner rotation built for the sample pages.
