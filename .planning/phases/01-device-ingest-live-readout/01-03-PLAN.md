<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ESP32 device -> POST /api/ingest | Untrusted network input (device could be spoofed, key could be stolen, payload could be malformed) |
| /api/ingest route -> devices/readings tables | Service-role client bypasses RLS entirely — this code path IS the access-control boundary |
| readings table -> anon Realtime channel | RLS policy is the only barrier between all rows and any anon-keyed subscriber |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-01 | Spoofing | `X-API-Key` auth check | high | mitigate | Combined `device_id`+`api_key` equality lookup against `devices` (service-role only); uniform 401 body regardless of which part failed (D-10) prevents enumeration of valid device IDs. |
| T-1-02 | Elevation of Privilege | Realtime `readings` RLS policy | high | mitigate | D-08 policy filters `"deviceId" = 'nb-001'`; Task 2's test mechanically proves a second device's row is never delivered to the anon subscriber. |
| T-1-04 | Denial of Service | Malformed/oversized ingest payload | low | accept | Zod validation rejects malformed bodies before insert; Vercel Hobby's 10s function timeout and default payload-size limits are the coarse backstop. No additional rate-limiting is in this phase's scope — acceptable for a single-device v1 demo. |
| T-1-05 | Information Disclosure | Plaintext `api_key` comparison/storage in `devices` | medium | accept | `devices` has zero anon/public read access (no RLS policy grants it, Plan 01); exposure requires a full DB/backup compromise, broader than this phase's auth mechanism. Hashing/rotation is explicitly deferred (CONTEXT.md Deferred Ideas) — accepted for v1 with that documented boundary. |
| T-1-06 | Tampering | Replay of a captured valid API key + old payload | low | accept | No nonce/timestamp freshness check in v1; replay requires the key to already be compromised (same prerequisite as T-1-01), and duplicate readings have limited impact before Phase 2's risk-scoring exists. Revisit if replay becomes a real vector in Phase 2+. |
</threat_model>
